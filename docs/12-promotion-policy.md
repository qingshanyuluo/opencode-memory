# 12 长期知识晋升政策

## 核心修正

“会话里确认过的事实”不等于“值得长期保存的知识”。长期库优先沉淀**方法、平台操作、工程约定和反复踩过的工具坑**；具体业务参数、用户 ID、临时实验状态、PR/commit 和组件当前状态机留在 L1 行为图，不默认晋升。

## 三问门槛

候选 entry 必须同时通过：

1. 30 天后仍大概率有效吗？
2. 换一个具体需求还能复用吗？
3. 能显著减少下一次探索或试错吗？

任一为否则跳过。

## 固定 role 与自由 kind

结构角色固定为 `interface / abstract / implementation / instance / resource`，供类加载器理解；`kind` 是自由中文业务分类（如排障规程、验证方法、平台手册），不参与结构语义。

Medium Pass 只创建 implementation/resource；interface/abstract 只能由多个实现经过 Deep Pass 提取。禁止把具体业务组件的参数、状态机或触发规则包装成接口。若无法上升为跨需求的方法，保留在行为图或 instance 即可。

## 双阶段策展

1. **候选提取**：从证据化行为图中找机制、决策、成功路径、死路和平台事实；
2. **主编审稿**：保留 2-6 个 implementation，共享依赖独立为 resource；合并窄条目，删除短命信息，将具体案例改写为跨需求方法。

第二阶段多一次小模型调用，但不在热路径；它解决的正是长期知识污染问题。

## 复现信号

organizer 会从 `bootstrap.db` 统计行为图中的技术词在全库和同项目出现过多少会话。例如首个样本中：

- BytePlus：84 个会话 / aichat-v2 58 个；
- Nacos：81 / 42；
- SLS 相关技能：58 / 46；
- Redis：192 / 55。

复现次数只表示“值得提炼”，不是自动判真。它帮助主编优先看到反复探索的平台与工具，而不是被单次业务细节占满上下文。

## 自动处理范围

自动 idle 整理只处理有 coding/operations 信号的主会话：文件编辑/补丁，或 git、构建、测试、kubectl、aliyun、docker、gh 等命令。普通咨询、旅行审批和个人事务默认跳过；子代理会话也跳过，避免与父会话重复晋升。

## 当前首批方法知识

经清理和重新整理后，首个复杂会话产出四类：

- BytePlus 实验分桶与未命中排查规程；
- dev 环境连通与 OBS/llm_raw 请求体验证手册；
- 共享 Redis 数据结构查询与可触达判定工程约定；
- Gradle 离线编译、测试执行确认与内网访问工具坑。

它们可在人类管理台修改或删除；管理台不设置批准流程。
